## 2. PRODUCT DEFINITION

**WebGen** is a web app where a user:

1. Types a brief: `"landing page for a coffee subscription called Roast Ritual, dark moody, premium"`.
2. Optionally picks: page type, industry, brand name, color mood, layout archetype, single vs multi-page.
3. Clicks **Generate**.
4. Watches a live streaming progress log while the backend does:
   plan → design system → write pages → validate → **auto-repair** → screenshot QA → bundle.
5. Gets an **in-browser live preview** (iframe, device toolbar: desktop/tablet/mobile, route switcher).
6. Can **edit with AI**: "make the hero darker and add a testimonials section" → the generator patches
   only the affected files and re-validates.
7. Clicks **Deploy** → site is live on a real HTTPS URL in ~30 seconds.
8. Can **Download ZIP** (fully self-contained, opens by double-click) or **Export to GitHub / CodePen**.

### Non-goals (v1)
No user accounts, no database, no billing, no multi-tenant isolation, no SSR. Static output only.

## 4. FUNCTIONAL REQUIREMENTS (every one is a hard acceptance criterion)

### 4.1 Generation
- `POST /api/generate` with `{ brief, options }` → **Server-Sent Events** stream.
- Event types: `stage`, `token`, `file`, `log`, `preview-ready`, `done`, `error`.
- Stages emitted in order: `analyze → plan → design-system → pages → validate → repair → screenshot → bundle`.
- Generation is **multi-call and incremental**: one call for the plan, one for the design system, then
  **one call per file**. Never one giant call for the whole site (reliability + token limits + streaming UI).
- Files written to `sites/<siteId>/` as they complete → preview updates live.
- Hard caps: 60 files/site, 250 KB/file, 45 s/call, 6 total retries with exponential backoff + jitter.
- On unrecoverable Gemini error: emit `error` with a human message and keep partial files.

### 4.2 The generated site itself MUST be
- **Responsive** at 360 / 768 / 1280 / 1920 with no horizontal scroll at any width.
- **Accessible**: semantic landmarks, one `h1`, labelled controls, visible `:focus-visible` rings,
  AA contrast (4.5:1 body, 3:1 large/UI), `prefers-reduced-motion` honored, no color-only meaning.
- **Functional**: nav links resolve, mobile menu works, forms validate + give inline errors +
  fake-submit success state, FAQ/accordion works, tabs work, modals trap focus and close on
  `Esc`, smooth-scroll works, "back to top" works, theme toggle (if dark mode) persists.
- **Zero console errors**, zero 404s, no `javascript:` / dead `href="#"`, no TODO/lorem ipsum left behind.
- **SEO**: `<title>`, meta description, OG/Twitter tags, canonical, `sitemap.xml`, `robots.txt`,
  `favicon.svg`, JSON-LD (`Organization` or `Product`/`Article` as appropriate).
- **Performance**: no render-blocking remote fonts (use `font-display:swap` + system fallbacks),
  images lazy + `width`/`height`, CSS/JS inline or deferred, Lighthouse Performance ≥ 90,
  Accessibility ≥ 95, Best Practices ≥ 90, SEO ≥ 95.
- **Safe**: no external scripts from unknown CDNs, no secrets, no eval of user HTML inside the parent
  app (preview is a sandboxed `iframe` with `sandbox="allow-scripts allow-forms allow-same-origin"`
  on a separate origin in prod, `srcdoc` in dev).

### 4.3 Editing
- `POST /api/edit` `{ siteId, instruction }` → model returns only the **changed files**
  (`{ changes: [{ path, action, content }] }`) + a one-line summary. Unchanged files are never rewritten.
- Deterministic apply: validate each change, apply, re-run the full gate, re-screenshot.

### 4.4 Deployment
- `POST /api/sites/:id/deploy` → uploads the static folder, returns `{ url, provider, deploymentId }`.
- Cloudflare: Direct Upload via the Pages API using a scoped API token + account ID.
  Fallback path when no token is configured: produce a **ready-to-paste** deploy manifest
  (`_headers`, `_redirects`, `wrangler.toml`, `netlify.toml`, `.github/workflows/deploy.yml`)
  and a single-command guide — the button must never dead-end silently.
- Print the live URL, QR code (SVG data URI is fine), and a shareable preview card.

### 4.5 Export
- `GET /api/sites/:id/bundle` → ZIP of the folder.
- `GET /api/sites/:id/single` → **one self-contained `index.html`** with all CSS/JS inlined
  (images inlined as data URIs when < 32 KB, else kept as files) — for "email it to a friend" use.

## 5. GEMINI INTEGRATION RULES

- Use the official `@google/genai` SDK. Endpoint: generativelanguage.googleapis.com.
- Every generation call MUST set:
  - `systemInstruction` (the master prompt, §6),
  - `responseMimeType: "application/json"` + `responseSchema` (§5.1) for **all** planning/design/edit
    calls — never parse prose,
  - `temperature`: plan/design `0.9`, code `0.35`, repair `0.2`,
  - `thinkingConfig.thinkingBudget`: `0` for simple calls, `-1` for the page-writing call,
  - `safetySettings` relaxed to `BLOCK_ONLY_HIGH` (marketing copy is not a safety problem),
  - explicit `maxOutputTokens` sized per call kind.
- Use **streaming** (`stream: true`) for the page-writing call so tokens can be counted live.
- Count tokens per call (`usageMetadata`) and aggregate per site. Display cost in the UI.
- Handle these explicitly:
  - `429 RESOURCE_EXHAUSTED` → backoff, then switch to the flash model,
  - `500/503` → retry with jitter (max 6),
  - `finishReason: "MAX_TOKENS"` → **never ship a truncated file**; re-request that file with a
    "continue from byte X" instruction or split the file,
  - `SAFETY`/`RECITATION` → retry once with a rephrased instruction, then fail that file loudly,
  - invalid JSON despite `responseSchema` → one repair round-trip asking for JSON only,
  - missing/placeholder `GEMINI_API_KEY` → the app must boot and show a setup screen with a link to
    AI Studio, not crash.
- Never let a model response write outside `sites/<siteId>/`. Sanitize every path:
  `path.normalize()` + reject `..`, absolute paths, and anything outside the allow-list of extensions
  (`.html .css .js .json .svg .png .jpg .webp .ico .xml .txt .webmanifest`).

## 8. VALIDATION & AUTO-REPAIR LOOP (this is what makes it "fully functional")

After every page is written, run `pipeline/validate.js`. **Any failure triggers a repair call scoped to
that file, up to 3 attempts, then the site is marked `degraded` with a visible report.**

**Structural (fast, no browser):**
- HTML parses (use `node-html-parser` or `parse5`), balanced tags, no unclosed elements.
- Exactly one `<h1>`; heading levels never skip (`h2→h4` is a fail).
- Every `href`/`src` resolves to an existing file in the bundle (ignore `#`, `mailto:`, `http(s):`).
- Every `<img>` has non-empty `alt` unless `aria-hidden`; every `<input>` has a `<label>`.
- Every `id` unique; every `aria-controls`/`aria-labelledby`/`for` points to an existing id.
- CSS parses; no `!important` spam (> 5 occurrences = fail); no leftover `{{TEMPLATE}}` tokens.
- JS parses (`new Function(src)` in a sandbox to check syntax only) and references no undefined ids.
- No `lorem ipsum`, `TODO`, `FIXME`, `example.com`, `undefined`, `NaN`, `[object Object]`.
- All colors used are defined tokens; contrast computed and passing.

**Functional (Playwright, headless Chromium):**
- Console error count === 0, page error count === 0, failed request count === 0.
- Click **every** `button, [role=button], a, summary, [onclick]` — assert no throw, assert the DOM
  actually changed where the element implies an interaction.
- Submit every form: empty → errors shown; invalid email → error; valid → success state.
- Keyboard: `Tab` through the page, assert a visible focus indicator on each stop; `Esc` closes overlays.
- `axe-core` scan injected → **zero critical/serious violations**.
- Screenshot at 390 / 768 / 1440; assert no horizontal overflow (`scrollWidth <= clientWidth + 1`).

**Performance:** run Lighthouse (mobile) once per site; below the §4.2 thresholds triggers repair.

Repair prompts are narrow: `Here is <file> and the exact failures. Return the corrected file only.`
Never regenerate unrelated files.

## 9. SECURITY & RELIABILITY (non-negotiable)

- API key: server-only, from env, validated at boot, never logged, never sent to the client.
- `helmet` with a CSP that blocks inline script from the parent app while allowing the sandboxed
  preview origin; `frame-src` limited to self.
- Rate limit: 10 generations/hour/IP (in-memory token bucket), plus a global concurrency cap of 2
  generations to protect the API key budget.
- Preview iframe sandboxed; generated HTML sanitized against `<script src=external>`, `<iframe>`,
  `on*=` handlers it didn't generate, and `javascript:` URLs.
- All path writes confined to `sites/<siteId>/` (see §5).
- Zip download: no path traversal (fixed archive entries, no symlinks).
- Deploy: tokens read from env, scoped minimally, never returned to the client.
- 404 + error handler that returns `{ error: { code, message } }` and logs a correlation id.
- Graceful shutdown; `/healthz` endpoint.
